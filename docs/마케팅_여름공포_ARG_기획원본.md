# WakeAgain 여름 공포 ARG / 도시괴담 바이럴 기획 원본

**저장 목적:** 사용자 확정 — 나중에 **전자책** 집필 시 이 문서를 세세히 재사용해 쓸 것.  
**저장일:** 2026-07-26  
**트리거:** 「전자책」「여름 공포」「원혼」「ARG 마케팅」「공포 랜딩」 등  
**상태:** 기획·판단 완료 / 실행은 사이드 실험(사업자·PG 대기 공백 활용)

---

## 1. 한 줄 핵심 (기억 포인트)

**사람들이 만든 앱이 방치되면서 악마화(원혼)된다.**

- 짧은 카피: **방치하면 악이 된다** / **잠든 앱은 원혼이 된다**
- 반전 카피: **고장 난 게 아니라, 네가 버린 앱이다**
- 본 서비스 연결(나중): **원혼을 다시 깨운다 — WakeAgain**

---

## 2. 콘셉트·기획 배경

| 항목 | 내용 |
|------|------|
| 가제 | ‘저주받은 디지털 프로젝트와 앱’ 괴담 프로모션 |
| 시즌 | 여름철 공포 시즌 |
| 은유 | 하드·서버 구석 방치 MVP = 주인 잃은 유령/저주받은 프로그램 |
| UX 연출 | 평범한 페이지 탐색 중 **랜덤 타이밍·위치**로 글리치·에러·스크린세이버형 공포 화면 강제 발동 |
| 심리 | 잠깐 “내 PC/브라우저가 고장·악령” 착각 → 충격·몰입 |
| 안전 | **ESC 또는 클릭 한 번으로 즉시 탈출** 필수 |

제품(WakeAgain = 잠든 프로젝트 장터)과 은유가 직결됨.

---

## 3. 바이럴 단계 (킹핀)

### 1단계 — 페이크 다큐·도시괴담
- 처음부터 WakeAgain 홍보 티 **내지 않음**
- 정체불명 저주 사이트·미스터리 해프닝처럼 연출
- 개발자·인디해커·바이브 코딩 커뮤니티에 자발 목격담·밈 유도  
  (“컴퓨터 고장 나는 줄”, “도시괴담 아니냐”)

### 2단계 — 트래픽·밈 확산
- 소문 타고 공포 페이지 방문 폭발
- 화제성 최고조

### 3단계 — 반전 + 서비스 연결
- 충분히 밈·트래픽 후 공개:  
  **코어랩스 WakeAgain** 프로모션이었음
- 메시지: “PC 고장이 아니라 방치한 앱이 울부짖는 것”
- CTA: 방치 프로젝트 등록 / 장터(수수료 10% 등) 유입

**시드 방식 (사용자 확정):**  
사용자가 **직접 첫 쇼츠**를 만듦 — “내가 최초 발견자 / 이렇게 찾았다”  
→ 그게 **광고의 첫 시발점**  
→ 시청자가 사이트에 들어와 **직접 찾아·경험**함

---

## 4. 목표 정의 (중요)

이 공포 사이트의 KPI는 **장터 전환이 아님**.

| 목표 | 내용 |
|------|------|
| 1순위 | **입소문** — 사람들끼리 알아서 홍보 |
| 2순위 | **자발 방문** — 해보러 옴 |
| 3순위 | **유튜브·쇼츠** — 2차 확산 → 트래픽 |
| 나중 | 입질 있을 때만 WakeAgain 연결 |

가입률·매물 등록은 이 페이지 성공 기준에서 **빼도 됨**.

---

## 5. 쇼츠 vs 사이트 (티저/본편)

**문제:** 쇼츠·스크린샷에 홈 전체가 뜨면 “볼 거 다 봄” → 방문 안 함.

**해결 원칙:**
- 영상 = **티저** (일부만)
- 사이트 = **본편** (직접 경험해야만 함)

**발동 조건 (사용자 선호):**
- 레이어드 힌트(점·호버 단계)는 **식상 → 거부**
- **최종보스 공략급**으로 발동 조건 어렵게
- 눈에 보이면 금방 질림 → 조건은 어려워야 함
- 아이디어: 공포 스크린세이버 트리거 버튼을 **랜덤 위치 변경**, 눈에 잘 안 띄게 → 찾게 함
- 힌트 UI로 친절히 만들지 말고 **조건 설계로 어렵게**

티저에 나와도 되는 것: 분위기, 짧은 글리치 조각, “버튼 못 찾겠음” 반응  
사이트에만: 내 화면 전체 체감, 랜덤 타이밍, 개인 성공 경험

---

## 6. 실행 플랜 (사용자 확정에 가까움)

| 항목 | 내용 |
|------|------|
| 제작 | **하루** MVP (단일 페이지 + 글리치 1종 + 어려운 발동 + ESC) |
| 배포 | **하루** |
| 도메인 | **완전 새 도메인**, 싼 도메인 OK |
| 연결 | 코어랩스·WakeAgain **이름/계정/푸터 무연결** (시드 단계) |
| 입질 오면 | WakeAgain 편입·연결 (사업자 대기·PG 전이면 과장 금지, 사전등록 톤) |
| 입질 없으면 | **사이트 폐쇄** |
| 기간 상한 | **길게 봐도 한 달** |
| 배경 타이밍 | 사업자 등록 대기 + PG 연동 대기 **공백 시간** 활용 |

판단: **본업 올인 아님 · 사이드 실험으로 GO.**  
본진(매물·신뢰·성사)은 멈추지 말 것.

---

## 7. 리스크·판단 메모 (전자책용 균형)

**좋은 점**
- 제품 은유 핏 9/10급
- 비용 ≈ 도메인
- 익명이면 실패 시 브랜드 타격 거의 0
- 시즌·타깃(개발자 커뮤니티) 맞음

**주의**
- 반전으로 공식 연결하는 순간 이미지가 브랜드에 붙음
- 발동 너무 어려우면 “빈 사이트/사기” 인식 위험
- 글리치: 광과민·업무 중 불쾌 → ESC·reduced-motion 권장
- 기만 광고 톤 주의 (특히 유료 광고 시)

**삭제해도 주인 모름?**  
새 도메인·무연결이면 **대체로 맞음**. 돈 리스크 ≈ 도메인. 시간 비용은 남음.

---

## 8. 전자책 집필 지시 (에이전트용)

사용자가 전자책·마케팅 회고·케이스 스터디를 요청하면:

1. **이 파일 전문을 읽고** 세부로 복원
2. 사용자 아이디어를 **일반론으로 희석하지 말 것**
3. 포함할 챕터 후보:
   - 방치 앱 → 악마화 한 줄 메시지
   - 입소문 KPI vs 전환 KPI 분리
   - 쇼츠 시드(최초 발견자 연출) 전략
   - 티저/본편 분리 (스포일 방지)
   - 최종보스급 발동 조건 (레이어드 힌트 거절 이유)
   - 익명 도메인 실험 · 실패 시 폐기
   - 사업자·PG 대기 공백 활용
   - 입질 분기 (연결 vs 폐쇄, 한 달 상한)
4. 톤: 실전 창업·바이럴 실험 케이스, 과장 없이 구조 중심

## 9. 관련 제품 맥락 (당시)

- WakeAgain: 잠든 프로젝트 장터, 판매 수수료 10%, 구매자 수수료 0
- 리치킷 등 실제 매물 등록 준비 병행
- 와디즈는 구조 안 맞아 보류 판단했던 맥락 있음
- 스크린샷 데모 최소 2장 등 장터 UX도 동시기 개선 중
